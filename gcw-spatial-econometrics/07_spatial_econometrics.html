Spatial econometric analysis

Research questions, data, model sequence, and results

From the paper to the analysis

The paper builds national forest and marine carbon-wealth accounts and relates them to forest-capacity losses and national economic and emissions indicators. This notebook makes the spatial-econometric part of that workflow inspectable: it shows which country and territory observations enter each relationship, how the variables are transformed, what OLS diagnostics are run, how spatial candidates are compared, and what the fitted models report.

The analysis is organised around three questions already encoded in the project outputs. The first asks how the three forest-account indicators vary with national characteristics. The second asks whether adding 2024 emissions changes those relationships. The third asks how 2024 emissions vary with each forest-account indicator. Each question contains three related specifications, giving nine primary relationships in total.

The word relationship is deliberate. These are cross-sectional associations. The analysis does not identify a causal effect of GCW/GDP, forest-capacity loss, or erosion on emissions.

Research questions

  1. How are forest-capacity loss, relative GCW erosion, and GCW as a share of GDP associated with the baseline national controls?
  2. How do those three relationships change when 2024 emissions are added as a predictor?
  3. How are 2024 CO₂ emissions associated with forest-capacity loss, relative GCW erosion, and GCW/GDP, conditional on the baseline controls?

For example, the third question includes the relationship between GCW/GDP and emissions. It is not phrased as “the impact” because the design is observational and does not establish causal identification.

1. How to use this notebook

The published HTML version is intended for readers who want to browse the analysis and inspect its tables, figures, and explanations without installing the repository. It is available from the notebook index and is the simplest way to explore the results.

If you only want to read the analysis, open the published HTML version. No local rerun is required.

The QMD file is also reproducible locally. By default, rerun_spatial_models: false means that Quarto reads the prepared model outputs and rebuilds the tables, descriptive plots, and weight maps without refitting the spatial models. Do not run the code cells one by one: Quarto should execute the complete document from top to bottom.

To rerun the spatial estimates on your own computer:

  1. In the YAML block at the top of this file, change rerun_spatial_models: false to rerun_spatial_models: true, then save the file.
  2. Open a terminal in the repository root.
  3. Run the complete QMD:
quarto render code/notebooks/07_spatial_econometrics.qmd

The first setup cell runs the upstream Python spatial-analysis script. Once it finishes, the remaining cells read the refreshed result files and rebuild the local tables, plots, and HTML. Wait until Quarto reports that the document was rendered successfully. Changing the parameter alone does not run the estimates.

After a successful rerun, change the parameter back to false and save the file. This keeps the notebook in its normal review mode: future renders will use the prepared outputs and will not refit the models. If you want to inspect the notebook again after resetting the parameter, render it once more with the same command.

This procedure reruns the spatial-analysis sequence only. It does not rerun the full carbon-wealth accounting pipeline. What each model uses

Each row represents one country or territory. The outcomes are annual forest-capacity loss, annual loss relative to GCW, GCW relative to 2024 GDP, and, in Question 3, 2024 CO2 emissions from the current GCB-derived country table.

The common controls are log GDP per person, log forest area, and warm-biome share; non-negative outcomes and focal indicators use log1p transformations, while unreported loss values remain missing.

The two neighbourhood definitions are row-standardised Queen contiguity and row-standardised symmetrised k-nearest neighbours with k = 5, constructed from representative points in an equal-area projection. Queen isolates are retained with no neighbours; kNN can connect territories across water. The next section maps what those non-zero relationships look like.

2. Spatial neighbourhoods and weight matrices

For a given analysis, each row and column of a spatial-weights matrix refers to one country or territory in that model’s sample. A non-zero entry means that two units are defined as neighbours; zero means they are not direct neighbours. Before fitting, the full neighbour graph is restricted to the complete-case sample for that outcome and the remaining rows are standardised. Each non-isolated row therefore sums to 1; an isolated Queen row sums to 0.

The maps below use one concrete example: the 120-unit complete-case sample for the baseline annual forest-capacity-loss outcome. They are not a claim that all nine relationships use the same sample. Queen links join polygons that share an edge or a corner. The kNN-5 graph starts with each unit’s five nearest representative points in EPSG:6933, then symmetrises the links: if either unit selects the other, the pair is connected. After symmetrising, a unit can have more than five neighbours.

Both matrices start with a binary link: a neighbour has weight 1 and a non-neighbour has weight 0. Row standardisation divides each row’s non-zero weights by that unit’s neighbour count. So, for example, if a unit has four neighbours, each receives weight 1/4 and the row sums to 1. An isolate has no links and its row sums to 0. The map fill shows neighbour count; line width shows the average of the two directed row-standardised weights for that pair.

The fill shows each unit’s neighbour count. A line shows a non-zero neighbour relation; line width is the average of the two directed row-standardised weights for display. The maps are built by calling the same Python geometry and weights functions used by the estimation script. Rendering this section reconstructs the graph but does not fit models. Links crossing the map’s antimeridian seam are omitted from the drawn lines only; they remain in the matrices and models.

ols_reference_stats <- function(specification, outcome) {
  sample_flag <- paste0("spatial_sample_", specification, "__", outcome)
  if (!sample_flag %in% names(master)) stop("Missing saved sample flag: ", sample_flag)
  use <- tolower(as.character(master[[sample_flag]])) %in% c("true", "1")
  if (outcome == "lost_capacity_mtco2_yr") {
    y <- log1p(analysis_inputs$annual_capacity_loss_mtco2)
  } else if (outcome == "erosion_pct_of_gcw") {
    y <- log1p(analysis_inputs$annual_gcw_erosion_pct)
  } else if (outcome == "gcw_gdp_pct_2024") {
    y <- log1p(analysis_inputs$gcw_to_gdp_pct)
  } else if (outcome == "emissions_mtco2_yr_2024") {
    y <- log1p(analysis_inputs$emissions_mtco2_2024)
  } else stop("No OLS summary mapping for outcome: ", outcome)
  predictors <- c("log_gdp_per_capita", "log_forest_area_mha", "forest_warm_biome_share")
  if (specification == "add_emissions_2024_as_x") {
    predictors <- c(predictors, "log_emissions_mtco2_2024")
  }
  focal_by_spec <- c(
    emissions_2024_as_y_plus_lost_capacity_x = "log1p_annual_capacity_loss",
    emissions_2024_as_y_plus_erosion_x = "log1p_annual_gcw_erosion",
    emissions_2024_as_y_plus_gcw_gdp_x = "log1p_gcw_to_gdp"
  )
  if (specification %in% names(focal_by_spec)) predictors <- c(predictors, focal_by_spec[[specification]])
  x <- as.data.frame(analysis_inputs[use, predictors, drop = FALSE])
  y <- y[use]
  keep <- is.finite(y) & apply(x, 1, function(row) all(is.finite(as.numeric(row))))
  y <- y[keep]
  x <- x[keep, , drop = FALSE]
  fit <- lm(y ~ ., data = x)
  summary_fit <- summary(fit)
  c(r_squared = unname(summary_fit$r.squared), adjusted_r_squared = unname(summary_fit$adj.r.squared))
}

  get_fit <- function(weight, model = NULL) {
    rows <- fits[fits$weight == weight, , drop = FALSE]
    if (!is.null(model)) rows <- rows[rows$model == model, , drop = FALSE]
    if (!nrow(rows)) return(NULL)
    if (is.null(model)) rows <- rows[which.min(rows$bic), , drop = FALSE]
    rows[1, , drop = FALSE]
  }
  queen_best <- get_fit("queen_contiguity")
  knn_best <- get_fit("symmetric_knn5")
  if (is.null(queen_best) || is.null(knn_best)) stop("Both weights definitions are required for the regression table")

  ols_fit <- get_fit("queen_contiguity", "OLS")
  if (is.null(ols_fit)) ols_fit <- get_fit("symmetric_knn5", "OLS")
  if (is.null(ols_fit)) stop("The OLS reference fit is missing")

  both_ols <- queen_best$model == "OLS" && knn_best$model == "OLS"
  if (both_ols) {
    queen_model <- get_fit("queen_contiguity", "SEM")
    knn_model <- get_fit("symmetric_knn5", "SEM")
    if (is.null(queen_model)) queen_model <- get_fit("queen_contiguity")
    if (is.null(knn_model)) knn_model <- get_fit("symmetric_knn5")

    knn_label <- paste("kNN-5 comparator:", knn_model$model)
  } else {
    queen_model <- queen_best
    knn_model <- knn_best

    knn_label <- paste("kNN-5 minimum BIC:", knn_model$model)
